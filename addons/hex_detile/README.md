# Hex Detiling shader

Copy this entire `hex_detile` folder, including both `hex_detile.gdshader` and its required `coherent_blend.gdshaderinc`, into `res://addons/hex_detile/`. Create a ShaderMaterial, select `hex_detile.gdshader`, and set repeatable albedo and matching OpenGL normal textures. Enable mipmaps on both textures. Set `texture_scale_m` for the size in world units and adjust `normal_strength`, `detile_blend_power`, and `detile_detrend` to taste. Tone normalization defaults to off because it can suppress texture detail. `detile_enabled` switches the sampling mode.

Optional: enable the Hex Detiling editor plugin in Project Settings, select a MeshInstance3D with no material override, and use the dock to create a material. The creation is undoable and will not replace an existing override. Projection is world-space. Rotation, blend contrast, and a deterministic variation seed are adjustable. Enable `paper_blend` to try luminance-weighted color and roughness plus slope-weighted normal blending; this can change how maps blend relative to one another. Roughness uses a constant unless a matching map is assigned and enabled. It costs more texture samples than ordinary tiling and can alter contrast. Profile your own scene.

The full repository includes the demo, comparisons, benchmarks, and credits. Code is MIT licensed; see LICENSE and THIRD_PARTY_NOTICES.md.

## Optional coherent mode

The default remains shared geometric weights (`coherent_blend=false`, `paper_blend=false`). Set `coherent_blend=true` for a content-guided mixture shared by color, normal slopes, and optional roughness. It takes precedence over `paper_blend`. Brightness and normal relief guide the mixture; `paper_falloff` sets content influence and `normal_strength` also controls the normal cue. Roughness follows the common mixture without steering it. `normal_blend_contrast` applies only to paper mode.

`coherent_filter=true` defaults on but only affects coherent mode. It relaxes sharp weights and content guidance with screen footprint, while keeping gradient-based texture sampling. This is heuristic blend relaxation, not a complete anti-aliasing solution, and can soften detail. No additional texture reads are needed relative to existing detiling at the same roughness and detrending settings. Default full PBR triplanar detiling uses 27 source-level texture reads (18 without roughness); optional detrending adds 12. Compiler and hardware costs still need profiling.

The full repository's `docs/coherent/README.md` describes the method, bounded fixture results, seventeen-material captures, structured-pattern failures, and reproduction commands. Shared weights already align map mixtures; the new mode should be selected by comparison on your own material.

## Optional structure-aware transforms

Set `structure_enabled=true` to replace free offsets and rotations with seeded integer translations on a supplied source lattice, independently of the selected blend mode. `structure_period` is the X/Y step in source UV (`1` means a full image repeat); `structure_stagger` adds that fraction of the X period per Y step. Each integer lies in `[-4,4]`. Zero period components lock their coordinate. Rotation is forced to identity while enabled. All maps share the transform and no texture reads are added.

Supply periods that preserve the motif, including checker color parity. Full-image-repeat shifts yield identical samples and no meaningful variation. Scanned layouts rarely match an ideal lattice exactly, so misalignment or ghosting can remain; this does not recognize patterns automatically. Constraints apply per triplanar projection and cannot enforce a global layout around corners. The demo offers approximate source-specific brick, plank, and checker presets; see the full repository's `docs/structure/README.md` for values, limitations, and evidence.

## Optional source-mask protection

Set `structure_guard_enabled=true` with `structure_enabled` and `detile_enabled`, and assign `structure_guard_map` as repeating mipmapped linear data. Black retains the original source material; white permits variation only when the donor mask is also safe. Missing maps default black. Rejected donor weight returns to the source without renormalizing surviving donors, with one common mixture for albedo, normal slopes and roughness. Active protection uses coherent blending regardless of the selected blend mode. The option defaults off and leaves existing presets unchanged.

Supply a conservative aligned mask; the addon does not segment materials automatically. Donor participation fades from full at two mask texels per pixel to zero at eight, returning to the original appearance at distance. This heuristic does not guarantee alias-free filtering. Exact zero source-mask or faded-detail values return the original material before donor sampling; partially faded values retain the full coherent mixture. Original pattern repetition remains, interior variation is restricted, and triplanar corners still mix projected layouts. Detrending changes donor color while protected source color remains raw, which can produce transition tone differences.

For a packed mask, set `structure_guard_in_albedo_alpha=true` and supply the linear mask in `albedo_map.a`. The flag defaults false, preserving the separate `structure_guard_map` API and its black fallback. Packed mask and albedo must share dimensions, UV alignment, repeat, mipmaps and filtering. Preserve RGB source color and alpha as independent linear data: disable alpha-border color repair, premultiplication and lossy channel compression when importing. The shader reads packed alpha from the same RGBA samples used for original and donor color, and uses albedo dimensions for the unchanged mask-footprint fade. Packing replaces the original albedo alpha, so use it for opaque materials that do not need that channel for opacity. The shader does not enable transparency.

With full PBR and no detrending, separate-mask guarding has 48 worst-case source-level triplanar reads; packing reduces that to 36 by sharing four mask/albedo fetches per projection. Exact source-only packed projections need three reads each (albedo, normal, roughness), or nine when all three return. Detrending adds up to twelve reads only on donor paths. These counts are not runtime timing estimates. Fresh Apple M5 / Godot 4.7.2 Compatibility comparisons measured shorter synchronous CPU render-call intervals with both changes: terrain 4.421 → 2.062 ms, close wall 4.111 → 3.523 ms, distant wall 1.007 → 0.874 ms (median of three round medians). Terrain varied substantially: frozen 4.421–4.735 ms versus optimized 2.058–3.828 ms. These intervals include possible driver/queue backpressure and exclude awaited scheduling; they are not GPU times, whole-frame latency or FPS. Profile your scene. The full repository's `docs/brick_guard/README.md` contains matched native crops and mask provenance; `docs/guard_optimization/VALIDATION.md` records packed-channel, matched-output, motion and four-way benchmark checks. The generic MIT addon excludes the example CC0 Brick 4 mask and source textures; obtain or author an appropriate mask for your own material.

## Prepared brick palette atlases

`brick_individual_enabled=false` defaults off. Enable it together with `detile_enabled`, `structure_enabled` and `structure_guard_enabled` to sample a prepared color-variant atlas with original, aligned source normal and roughness maps. Set `brick_individual_map` and `brick_individual_tiles_per_axis` to match the atlas; the tile count defaults to four for compatibility. Each atlas tile must retain the full source resolution and identical mortar/fine-detail coordinates. A 2×2 atlas made from a 1024² source is 2048², not a resized 1024² texture.

The atlas stores source-aligned color variants and repeating guard data in alpha. Native protected pixels must retain original RGB. Import losslessly with mipmaps, repeat and the source-color sampler; disable alpha-border repair and premultiplication, and preserve RGB beneath zero alpha. Alpha remains linear data and does not enable transparency. The original source albedo and matching PBR maps remain bound for ordinary modes and comparison. Atlas size alone does not guarantee quality: a small variant set can retain repeating per-brick color bias. Use the tested preprocessing and inspect new materials.

`brick_individual_stochastic=true` mixes three atlas samples with smooth shared weights. Every offset is an integer source-tile shift, so all donors retain the same mortar and fine-detail phase. The variation seed changes their world arrangement. Coarse color fades toward the atlas mean; it does not restore the original repeating stains. Original normal/roughness coordinates remain aligned with the original fine RGB template. This deliberately replaces coherent donor PBR mixtures in near interiors. Blend contrast, paper weights and donor detrending do not steer this route; normal strength, optional roughness and texture scale still apply. All existing modes retain their behavior when the option is off.

The method requires a prepared, source-specific mask and color atlas. It does not automatically recognize bricks, synthesize new mortar geometry or create globally continuous brick courses around triplanar corners and curved surfaces. Original joint shapes and protected rim details can remain recognizable. The full project's `docs/brick_atlas_release/AUTHORING.md` covers authoring constraints; its validation records identify tested settings, sources, memory and rendering costs. Example CC0 sources and atlas-generation scripts belong to the full project rather than the standalone MIT addon archive.

The full project retains Brick 4 at 4×4 as the qualified reference. Compact 2×2 and 3×3 trials missed a strict intermediate luminance condition; balanced 2×2 is a documented memory/quality tradeoff, not an equivalent default. A 4×4 1024²-source atlas contains about 85.3 MiB of theoretical uncompressed RGBA8 texels including mipmaps; actual allocation/residency is not measured by that estimate. Matched Apple M5 CPU render-call tests improved close-wall/sphere intervals but were slower at the distant wall; no GPU or universal speedup claim follows. The additional Red Brick/Large Red Bricks examples also missed full qualification and are disabled in the demo palette mode. Read the full project’s `docs/brick_atlas_release/README.md` before choosing an atlas size or authoring another material.
