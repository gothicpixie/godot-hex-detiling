# Offline broad-tone normalization

The experimental `assets/gallery/brick_4_albedo_guard_normalized.png` is a separate copy of the packed Brick 4 albedo. It reduces broad luminance differences without moving texture coordinates or averaging the final RGB pixels. Its alpha is byte-for-byte the existing interior mask. Original albedo, packed albedo, normal, roughness and mask files remain unchanged. Attribution remains **Rob Tuytel / Poly Haven, CC0**; upstream URLs/hashes are in [SOURCES.json](../../assets/gallery/SOURCES.json), with mask derivation in [source-mask.json](../brick_guard/source-mask.json).

The script decodes RGB using the sRGB transfer function, derives linear Rec.709 luminance, and applies a periodic Gaussian low-pass with sigma 64 source pixels. This scale spans multiple joints and approximately two brick widths; it does not identify individual bricks. A scalar multiplicative correction moves that broad field toward its geometric mean at strength 0.65. The gain is bounded to 0.85–1.18 before one global exposure adjustment reserves highlight headroom. The selected asset uses gain 0.8821–1.0685 after a global factor of 0.96034. No gain-bound saturation or RGB clipping occurs. Every RGB channel receives the same local gain, preserving linear color ratios before 8-bit rounding. Alpha is copied separately.

All source pixels keep their positions; only the broad correction field is filtered. Thus the operation does not resample or blur mortar edges, and it retains high-frequency multiplicative detail before quantization. Their absolute RGB values do change, including mortar RGB. The gain varies by at most 0.00117 between adjacent texels. Wrapped filtering ensures the correction uses opposite sides of the repeating tile as neighbors; it does not repair discontinuities already present in the source.

The [candidate sheet](normalization-candidates.jpg) shows RGB alone for the source and strengths 0.40, 0.65 and 0.80. Inspection favors 0.65 as a modest correction while retaining individual brick colors, chips, fine dark marks and mortar contrast. This is a source-image judgment, pending matched engine renders and motion. Luminance-only correction intentionally retains broad chromatic differences and repeated brick shapes; it does not remove every recognizable repeat. It lowers mean linear luminance by about 4.2% because the global headroom factor prevents clipping existing bright specks. A scene blending this copy with the original must account for that bounded tone change.

At sigma 64, broad luminance standard deviation falls from 0.01142 to 0.00598. Relative to mean luminance, it falls from approximately 0.0570 to 0.0312, so the reduction is not explained solely by darkening. Adjacent log-luminance edge correlation is 0.999896; signs agree for every tested strong edge (absolute adjacent log contrast above 0.10), and median strong-edge contrast ratio is 1.0022. These are numerical preservation checks, not a perceptual quality guarantee. Alpha equality covers all 1,048,576 pixels. The saved PNG round-trips exactly to the generated bytes, all linear samples are finite/in range, and no RGB channel is clipped.

Regenerate with Python, Pillow, NumPy and SciPy:

```sh
python3 scripts/normalize_guard_albedo.py \
  assets/gallery/brick_4_albedo_guard.png \
  assets/gallery/brick_4_albedo_guard_normalized.png \
  --sigma 64 --strength 0.65 --evidence docs/distant_brick
```

[normalized-albedo.json](normalized-albedo.json) records source/output/channel hashes, parameters, library versions and CPU metrics. The import sidecar follows the [packed-channel requirements](../guard_optimization/PACKING.md): lossless mode, mipmaps, identity channels, no alpha-border repair or premultiplication, and no automatic normal/roughness/3D compression processing. This is an opaque packed material copy; alpha is guard data.

The earlier [two-band prototype](../../experiments/two_band/README.md) changed runtime donor band blending and did not establish an improvement. This preprocessing instead applies a bounded smooth gain to each original texel and introduces no runtime band decomposition. It does not establish a successful distant-variation shader; that separate experiment must be judged from engine output, repeated layouts, transition behavior, camera motion and cost.
