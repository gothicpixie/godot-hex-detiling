# Brick atlas release candidate

The user approved four steps: try a smaller atlas while retaining native source resolution; measure memory and rendering against v0.7.0 and the accepted 4×4 candidate; if quality holds, extend to additional real brick materials and wall/corner/curved meshes; package the successful result with settings, comparisons and limits. Work on `codex/brick-atlas-release`, based on 0f5322a. Root reviews final evidence before any version, commit, merge or publication action.

Parameterize the existing aligned stochastic sampler with `uniform int brick_individual_tiles_per_axis = 4`. The compatibility default retains the accepted 4×4 sampler. Divide atlas UV and gradients by the configured tile count; generate only integer original-source offsets in its range. Keep source PBR coordinates, squared shared barycentric weights, grid scale, alpha-zero handling and coarse atlas-mean fade unchanged. New 2×2 assets are separate files with 1024² source tiles, not downsized copies; original and 4×4 assets remain immutable. Select 2×2 in the demo only after the quality gate passes.

GPU evaluation compares original v0.7.0, frozen accepted 4×4, and new 2×2 at matched settings. Retain source- and atlas-period color/luminance metrics, palette and fine-detail retention, protected native RGB/PBR, mortar edge tails and matched motion. Distinguish theoretical uncompressed texel storage from measured allocation/residency. Measure the same synchronous CPU render-call interval for all rendering arms; report GPU timing only if valid nonzero samples exist. Do not turn source-level fetch counts into timing claims.

After the gate, integrate at least two additional actual brick sources with matching albedo, normal, roughness and authored or source-specific derived guard masks, explicit provenance and source alignment. This is source-specific preparation, not automatic brick recognition. Data-driven presets expose only supported, tested sources. Preserve existing material indices/defaults and the generic separate-mask API; prior failed macro mode remains clearly experimental and opt-in. New colors retain aligned original PBR. Test flat walls, corners and curved triplanar surfaces without promising global brick continuity across projections.

Prepare a coherent potential v0.8.0 addon package only after the retained implementation and quality/performance/material evidence are reviewed. Document generic atlas dimension/import/tile-count requirements, supported demo settings, memory/rendering limits and actual comparisons. Include required shader/helper/UID/license files, exclude example CC0 assets from the standalone addon, and preserve their provenance in the full project. Root authorizes final release operations separately after review.
